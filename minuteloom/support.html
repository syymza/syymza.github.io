MinuteLoom help: backups, imports and reports

Help for MinuteLoom, the local time-tracking app by Daniele Zanni. UI labels may be translated on your device.

Questions? Email daniele@duck.com. Include the app version, your iOS version and the steps leading to the issue. Please redact private client details and do not attach your ledger unless necessary. See our privacy policy for support-message handling.

Keep a recoverable copy

Stop the running timer. In Reports, choose Save a backup, select a destination in the system file picker, and finish saving. Keep the resulting JSON file in a place you can find again. Backups include all projects and entries, not just the selected report dates or project. CSV and PDF reports are not importable backups.

The app does not encrypt exported backups or reports. Choose a destination with appropriate access controls and avoid sending files containing client names or notes to people who should not see them. Device backups depend on your iOS settings. Saving in a cloud-backed Files location does not enable automatic app sync.

Import without overwriting local edits

Stop the timer, open Reports and choose Import a backup. Select the JSON file, review the preview, then choose Import missing records if it is the file you intend to import. Cancel to leave your ledger unchanged.

Import matches projects and entries by their stored record IDs. Missing IDs are added; unchanged matching records are skipped. If a matching record differs from a local edit, the entire proposed import is rejected. The app does not merge the conflicting versions or offer an automatic overwrite. Recreating the same session with a different ID is not treated as the same record.

If a conflict occurs, keep both your existing ledger and the backup. Do not delete local records or edit IDs in the JSON merely to force an import. You can export reports to inspect records separately, but a report is not a replacement backup.

When a saved ledger cannot be read

The app has a distinct Recover from backup flow while the saved ledger is unreadable. Choose a valid backup with a stopped timer, review the preview, then use Preserve original and restore backup only if you intend to recover from that file. The app first retains a separate copy of the unreadable original and verifies that copy before attempting replacement.

This is different from normal import and does not guarantee recovery of data missing from your backup. Do not uninstall the app or delete its files as a troubleshooting shortcut: that can remove the only remaining local copy. Keep available backup files unchanged.

Why a file may be rejected

  • Backups with a running timer cannot be imported. Create a new backup after stopping the timer in the source app.
  • The stored ledger and JSON backup limit is 25 MiB (shown in the app as 25 MB).
  • Unsupported formats, invalid records, duplicate record IDs, missing project references and conflicting edits are rejected rather than silently repaired.
  • A combined import can exceed the saved-ledger limit even if both files individually fit it.

Why report totals may differ from expectations

Reports include completed entries only. Date selection uses the device's current time zone, and a session crossing a selected date boundary contributes only the part inside the selected dates. Overlapping entries count separately. Different currencies are totaled separately, without currency conversion.

Rates and currencies are saved with each session. Changing a project rate does not rewrite older sessions. Totals use unrounded amounts; displayed rounded rows can differ from the displayed total by a small rounding amount. CSV retains numeric precision.

Large exports

PDF is limited to 500 entries and an estimated 200 KB of report text. CSV is limited to 10,000 entries and an estimated 20 MB of report text. Choose a smaller date range or a single project if an export is too large; CSV may work for a report too large for PDF. These limits are separate from JSON backup limits.

Timer after a clock change

The timer retains its saved start time when the app is closed and reopened. It uses the device clock, not a separate billing clock. Review the recorded session after changing the device time. MinuteLoom is a personal time record, not an invoicing, payroll or payment-processing system.
